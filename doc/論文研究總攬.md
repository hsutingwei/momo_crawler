# 文本前處理與斷詞工程分析

本文檔根據 `preprocess_v2.py` 之原始碼，梳理實際的文本前處理與斷詞執行流程。以作為後續特徵工程與模型建構的基礎。

## 一、高階流程圖節點列表 (論文架構用)

此層級可作為論文 3.3.3 節的流程圖文字說明：

1. **資料讀取與格式修復**：讀取原始 CSV，並修復因斷行產生的格式錯誤。
2. **無效與重複資料排除**：驗證欄位完整性，並透過評論 ID 排除重複抓取的資料。
3. **基礎文字正規化**：將商品名稱與評論文本進行 Unicode 統一化、繁簡轉換、並清除網址與控制字元。
4. **字元過濾與替換**：過濾非中文字符與特殊標點，並將其替換為特定分隔符號 (`;`) 以保留斷句結構。
5. **空文本檢驗**：若清理後文本為空，則判定無實質語意並跳過後續詞彙處理。
6. **CKIP 斷詞與詞性標記**：將通過保留的中文句子交由預訓練之 CKIP Transformer 模型進行分詞與詞性標記。
7. **長詞彙拆分優化**：針對分詞過長之字詞 (>4字)，透過資料庫中的輔助子詞字典進行「右向左最大匹配」拆分。
8. **結果聚合與輸出**：將正規化後的文本與對應的標記結果儲存為 CSV 與 JSONL 格式供後續使用。

## 二、詳細流程圖節點列表 (反映程式邏輯)

本列表精確反映程式碼中的先後執行邏輯、輸入輸出關係與條件分支。

### 步驟 1：修復斷行與讀取 (repair_broken_csv)
*   **輸入**：原始爬蟲 CSV（例如 `<keyword>_商品留言資料_<ts>.csv`）
*   **處理動作**：使用正規表示式逐行檢查是否以 `流水號,` 開頭；若否，則合併至上一行。
*   **輸出**：修復後的暫存 CSV 檔案 `_tmp_...csv`。

### 步驟 2：欄位與重複驗證 (process_file - Iterate CSV)
*   **輸入**：逐筆讀出 `_tmp_...csv` 之中每一列 (row)
*   **處理動作 & 條件判斷**：
    *   **條件 A**：欄位長度是否 `< 7`？
        *   *[分支：是]* → 視為無效行，並 **排除該筆評論**。
        *   *[分支：否]* → 繼續。
    *   **條件 B**：提取 `msg_id` (`row[6]`) 是否已存在於 `seen_ids` 集合？
        *   *[分支：是]* → 視為重複，並 **排除該筆評論**。
        *   *[分支：否]* → 繼續，並登記至集合中。
*   **輸出**：有效的原始商品名稱與留言字串。

### 步驟 3：基礎文字正規化 (normalize_text)
*   **輸入**：原始商品名稱 `row[1]` 與原始留言 `row[5]`
*   **處理動作**：
    1.  **Unicode 正規化**：執行 `unicodedata.normalize('NFKC', s)` 處理半形與全形等相異編碼。
    2.  **繁簡轉換**：執行 OpenCC (`s2tw`) 將簡體中文轉為台灣繁體。
    3.  **特殊符號清理(URL)**：使用正規表示式移除網址 (http/www) 並以空白替換。
    4.  **特殊符號清理(控制字元)**：移除 `\u0000-\u001F` 等十六進制控制字元並以空白替換。
    5.  移除多餘空白片段使其為單一空白。
*   **輸出**：初步清洗過之正規化字串 `norm_text`。

### 步驟 4：中文字元過濾 (sanitize_chinese)
*   **輸入**：初清洗的 `norm_text` 字串
*   **處理動作**：
    1.  **非中文字符清理**：將所有非 CJK (中日韓越漢字) 編碼範圍內的字元，強制替換成符號 `;`。這意味著**英文及數字都會被排除並被視為分隔符**。
    2.  **特殊符號替換**：明確將大部分之各類標點、注音符號等強制轉為符號 `;`。
    3.  連續之分隔符號 (`;;;`) 自動合併為單次 `;`。移除頭尾的分隔符。
*   **輸出**：僅保留各種漢字，其餘皆被分號區隔的文本段落。

### 步驟 5：斷詞判定與 CKIP 分詞 (ckip_tokenize)
*   **輸入**：經過字元過濾後的 `norm_text`
*   **處理動作 & 條件判斷**：
    *   **空字串判定**：判斷 `if not norm_text:`
        *   *[分支：是]* → 即留言只含網址、純英數等，**排除後續分析，回傳空詞彙與空詞性 `([], [])`**，進入步驟 7 輸出。
        *   *[分支：否]* → 繼續進入 CKIP 分詞引擎。
    *   分詞處理：調用 GPU 加速之 `CkipWordSegmenter` 進行文本分詞，以及 `CkipPosTagger` 進行詞性還原（POS標記）。
*   **輸出**：斷詞列表 `tokens` 與 詞性列表 `poses`。

### 步驟 6：長詞彙拆分補強 (split_long_tokens_with_pos_rmm)
*   **輸入**：斷詞與詞性陣列、長度2至3之輔助字典 `dict_set`
*   **處理動作**：
    *   若單一 token 長度大於 4 (包含 5 以上)：
        *   優先比對字典內的 3 個字子詞，若不匹配則比對 2 個字。
        *   以最大反向匹配 (由右向左切)，確保末端詞語結構；拆解後的附屬子詞繼承此 token 最原本的詞性。
*   **輸出**：最終優化與細碎化後之 `out_tokens, out_poses`。

### 步驟 7：資料輸出組合
*   **輸入**：最終的文字與陣列與 ID。
*   **處理動作**：將 `norm_text` 附加為 CSV 新欄位、並打包 JSON 格式。
*   **輸出**：產生 `pre_..._norm.csv` 與 `pre_..._tokens.jsonl`，準備進入下階段的 TF-IDF 頻次抽取。

#### 論文建議說法
> Δ=10 的選擇與銷售級距概念一致：相鄰低級距之間最小差距為 5~10，因此 Δ=10 作為「有意義的銷售成長」最低門檻，可過濾純統計噪音。

#### 銷售級距（Sales Buckets）
銷售量按以下離散區間分桶，label 定義基於「跨越幾個 bucket」：
```
[0, 1, 5, 10, 20, 30, 50, 100, 500, 1000, 3000, 5000, 8000, 10000, 30000, 50000, ...]
```

#### 標籤模式（Label Mode）
| 模式 | 說明 |
|------|------|
| `next_batch` | 比較截止日前後兩個最近批次的銷售量 |
| `fixed_window` | 在截止日後固定的時間窗口（`label_window_days=7`天）內，看銷售量是否達標 |

#### 正類定義（爆品 = Positive Label）
- `y = 1`：商品在截止日後的快照中銷售量顯著增加（滿足 delta + 可選 ratio 條件）
- `y = 0`：銷售量未顯著增加（非爆品）

## 2️⃣ Preprocessing Pipeline（資料前處理流程）

### 文本處理步驟（preprocess_v2.py）

```
原始評論 CSV
  ↓ 1. 換行字元修復 (repair_broken_csv)
  ↓ 2. Unicode 正規化 (NFKC) — 全形→半形
  ↓ 3. 簡→繁轉換 (OpenCC: s2tw)
  ↓ 4. 移除 URL、控制字元、規整空白
  ↓ 5. 保留漢字，非中文替換為分隔符 ';' (sanitize_chinese)
  ↓ 6. CKIP BERT 斷詞 + POS 詞性標注 (CkipWordSegmenter, bert-base, GPU)
  ↓ 7. 長詞後向最大匹配切分 (RMM, 3字→2字→單字)
  ↓ 輸出: norm_text (CSV) + tokens/POS (JSONL)
```

### 斷詞過濾策略（seg.py + preprocess_v2.py）
- **保留詞性**：名詞 (`N*`) + 動詞 (`V*`)（CKIP POS tag）
- **去除單字詞**：`len(token) > 1` 才保留
- **不使用傳統停用詞表**：改以詞性標注自動過濾助詞、語氣詞等

### 文本特徵方法

| 方法 | 實作 | 用途 |
|------|------|------|

| Feature Name | Description | Method |
|---|---|---|
| `feat_entropy_tfidf` | 語意熵（TF-IDF版，K-Means 5群 Shannon Entropy） | KMeans(5) + scipy.stats.entropy |

| `feat_temporal_burstiness` | 時間突發性（評論間隔時間的 Burstiness 指標） | [(r-1)/(r+1)](file:///c:/YvesProject/%E4%B8%AD%E5%A4%AE/%E7%B7%9A%E4%B8%8A%E8%A9%95%E8%AB%96/momo_crawler-main/build_tfidf_index.py#259-335), r=std/mean of IAT |

### D. 融合 / 交互特徵（Fusion / Interaction）

| Feature Name | Description | Formula |
|---|---|---|
| `quality_driven_momentum` | 品質驅動動量 | `kin_acc_abs * category_fit_score` |

| `momentum_tfidf` | 動量（TF-IDF版） | `kin_acc_abs * (category_fit_score+0.5) * (feat_entropy_tfidf+0.5)` |

| `validated_velocity` | 驗證速度（音量加權） | `ratio_recent30_to_prev60 * log1p(comment_3rd_30d)` |
| `novelty_momentum` | 新奇動量 | `ratio_recent30_to_prev60 * (1 - repurchase_ratio_recent)` |
| `price_weighted_arousal` | 價格加權情緒 | `bert_arousal_mean * log1p(price)` |

| `is_mature_product` | 是否為成熟商品（二元旗標） | [(comment_count_pre > 50) OR (repurchase_ratio > 0.2)](file:///c:/YvesProject/%E4%B8%AD%E5%A4%AE/%E7%B7%9A%E4%B8%8A%E8%A9%95%E8%AB%96/momo_crawler-main/build_tfidf_index.py#259-335) |
| `spam_risk_score` | 垃圾刷評風險分數 | 觸發條件: count_90d>5 AND entropy<0.5 → 值=kin_acc_abs |

## 6️⃣ Experiment Pipeline（實驗流程）

### Pipeline 設計（train_v2.py 7-Phase ML Pipeline）

```
Data (PostgreSQL DB)
│
├─ load_product_level_training_set() [data_loader.py]
│   ├─ SQL: 計算所有 Dense 特徵（SQL aggregation）
│   ├─ SQL: 計算 Label y（next_batch / fixed_window）
│   └─ Python: SBERT/TF-IDF/Compression 特徵計算
│
├─ Phase 1: 初始化 Run（run_id, output dir, Git info）
├─ Phase 2: 資料切分
│   ├─ Stratified 8:2 Holdout Split（固定 random_seed=42）
│   └─ Stratified K-Fold CV on train_pool（預設 10 folds）
├─ Phase 3: TF-IDF Prefit（僅在 train_pool 上 fit，test 只 transform）
├─ Phase 4: K-Fold 訓練迴圈
│   ├─ Dense features → FeatureTransformer（fit only on train_fold）
│   ├─ TF-IDF → slice from prefit matrix（無洩漏）
│   ├─ Merge: hstack([dense_transformed, tfidf_sliced])
│   ├─ Data Leakage Check（5項自動化洩漏檢查）
│   └─ 訓練 → 預測 OOF → 計算 AUC, F1, Precision, Recall
├─ Phase 5: 最終模型訓練（用完整 train_pool，同 prefit TF-IDF）
├─ Phase 6: Threshold 調整（fixed=0.5 / tuned=OOF F1 / locked）
└─ Phase 7: 儲存 Artifacts + 資料庫記錄
```

### 消融研究（Ablation Study）支援
- 使用 `--force-use-splits` 強制使用相同切分（保證對照實驗公平性）
- 使用 `--hyperparameter-mode locked` 鎖定超參數（消除超參誤差）
- 使用 `--threshold-mode locked` 鎖定閾值
- `split_hash / dataset_hash / feature_hash` 紀錄可復現性

## 8️⃣ Evaluation Metrics（評估指標）

### 分類任務類型
- **二元分類（Binary Classification）**：爆品（1）vs 非爆品（0）

### 評估指標

| 指標 | 說明 | 程式實作 |
|------|------|---------|
| **ROC-AUC** | 主要比較指標；不受閾值影響 | `sklearn.metrics.roc_auc_score` |
| **F1-Score** | 精確率與召回率的調和均值（應對不平衡） | `sklearn.metrics.f1_score` |
| **Precision** | 精確率 | `sklearn.metrics.precision_score` |
| **Recall** | 召回率 | `sklearn.metrics.recall_score` |

### 評估策略

| 評估集 | 說明 | 輸出 |
|--------|------|------|
| **OOF（Out-of-Fold）Aggregate** | 每個 fold 的均值 ± 標準差 | `AUC_mean ± AUC_std, F1_mean ± F1_std` |
| **OOF Global** | 拼接所有 fold 的 OOF 預測計算 | 單一 AUC, F1, Precision, Recall |
| **Test Set** | 最終模型對 holdout 20% 的預測 | AUC, F1, Precision, Recall |

### 分類閾值（Decision Threshold）
| 模式 | 說明 |
|------|------|
| `fixed` | 固定 0.5 |
| `tuned` | 在 OOF 預測上搜尋最佳 F1（步長 0.01） |
| `locked` | 使用 baseline 實驗的最佳閾值（消融研究用） |

## 9️⃣ Data Split（資料切分）

### 切分策略

```
全部資料（N 個商品，排除 v2_error_prod 過濾清單）
     ↓ Stratified 8:2 Split（random_seed=42）
┌──────────────────────────────────┐
│ Train Pool (80%)                 │
│  ↓ Stratified 5-Fold CV ✅       │
│  ┌ Fold 0: train 4/5 + val 1/5  │
│  ├ Fold 1: train 4/5 + val 1/5  │
│  ├ ...                           │
│  └ Fold 4: train 4/5 + val 1/5  │
└──────────────────────────────────┘
┌──────────────────────────────────┐
│ Test Set (20%)                   │
│  → 僅用於最終評估，從不參與訓練  │
└──────────────────────────────────┘
```

| 參數 | 值 |
|------|---|
| **Train/Test Split** | 80% / 20% |
| **K-Fold** | Stratified K-Fold, **K=5** ✅ |
| **Random Seed** | 42（固定，保證可復現）✅ |
| **Holdout Strategy** | Stratified（保持正負類比例） |
| **分析單位** | Product Level（每筆 = 一個商品） |

### 資料洩漏防止（Data Leakage Prevention）
- TF-IDF Vectorizer 僅 fit 在 `train_pool`（80%），test set 只 transform
- Dense 特徵的 FeatureTransformer 僅 fit 在 `train_fold`（每個 fold 的訓練部份）
- 5 項自動化洩漏檢查（[leakage_prevention.py](file:///c:/YvesProject/%E4%B8%AD%E5%A4%AE/%E7%B7%9A%E4%B8%8A%E8%A9%95%E8%AB%96/momo_crawler-main/Model/leakage_prevention.py)）於每個 fold 執行
- 截止日設計保證：特徵（cutoff 前評論）與標籤（cutoff 後銷售）嚴格分離

## 10️⃣ Full Research Workflow（完整研究流程）

```
1. 資料收集層（Data Collection）
   crawler.py + crawler_pipline.bat
   → Selenium 爬蟲：搜尋結果頁 + API 抓評論 + 銷售快照
   → 輸出: {keyword}_商品資料.csv, crawler/{keyword}_商品留言資料*.csv

2. 資料入庫層（Data Ingestion）
   csv_to_db.py
   → 資料驗證 + 去重 + 批量寫入 PostgreSQL
   → 資料表: products, sales_snapshots, product_comments

3. 文本前處理層（Text Preprocessing）
   preprocess_v2.py
   → 換行修復 → Unicode/繁簡正規化 → 去除 URL/控制字元
   → CKIP BERT 斷詞 + POS 標注（GPU 加速）
   → 輸出 JSONL: {msg_id, norm_text, tokens, pos}

4. TF-IDF 索引建立層（TF-IDF Indexing）
   upload_preprocessed_to_db.py → comment_tokens 表
   build_tfidf_index.py
   → 計算全語料 TF/DF → 寫入 tfidf_vocab / tfidf_term_freq / tfidf_doc_freq

5. 特徵工程層（Feature Engineering）
   data_loader.py (load_product_level_training_set)
   → SQL: 計算運動學特徵（kin_v1/v2/v3, acc, jerk）
   → SQL: 計算 BERT 語意特徵（arousal 等 5 個維度）
   → Python: 計算資訊理論特徵（entropy, burstiness, diversity, compression, NCD）
   → Python: 計算融合特徵（authentic_momentum, spam_risk_score 等）
   → SQL: 計算標籤 y（next_batch 或 fixed_window 策略）

6. 模型訓練與評估層（Model Training & Evaluation）
   train_v2.py
   → Stratified 8:2 holdout split + 10-Fold Stratified CV
   → TF-IDF prefit（train_pool only）
   → K-Fold 迴圈訓練（XGBoost / LightGBM / LR / SVM）
   → 不平衡處理（scale_pos_weight）
   → 洩漏檢查（5 項自動化）
   → OOF 評估 + 最終模型訓練 + Test 評估

7. 結果記錄層（Result Logging）
   → 輸出 artifacts: splits.parquet, metrics.json, predictions_oof.parquet 等 15+ 個文件
   → 寫入 PostgreSQL 實驗追蹤表（ml_runs 等）
   → 支援消融研究重現
```

# 時間範圍.md

# 時間範圍（Time Range）

本文件用於明確定義本研究的時間相關設定：**觀測期間（observation window）**、**標籤切分日/截點日（label split / cutoff date）**，以及**建模時可用資訊的截止日（避免資料洩漏）**。

---

## 1️⃣ 欄位與時間語意

在資料表查詢中（以 `product_comments pc` 為主）：

- **評論時間（event time）**：`pc.comment_date`  
  - 代表評論「發生」的日期/時間（使用者在平台留下評論的時間）。
  - 研究中凡是「評論行為在時間上的變化」與「時間窗統計特徵」原則上都應以此欄位為準。

- **爬取時間（ingestion / capture time）**：`pc.capture_time`  
  - 代表爬蟲「取得/寫入」該評論到資料庫的日期/時間。
  - 用於判定「在某個時間點 \(T\) 做預測時，哪些資料**已經可得**」，以避免把 \(T\) 之後才爬到的資料誤用到 \(T\) 當下的特徵（資料洩漏）。

> 核心區分：  
> **`comment_date` 是事件發生時間；`capture_time` 是資料進庫時間。**  
> 當需要「as-of \(T\)」的可用資料集時，通常要同時限制 `comment_date <= T` 與 `capture_time <= T`。

---

## 2️⃣ 觀測期間（Observation Period）

### 2.1 定義

- **觀測期間**：本研究納入分析的評論事件範圍  
  \[
  [D_{start},\; D_{end}]
  \]
  其中 \(D_{start}\) 與 \(D_{end}\) 以 **`pc.comment_date`** 的最小/最大值（或研究設計指定的邊界）定義。

### 2.2 實務建議（可重現寫法）

- **資料收集上限（as-of 上限）**：若要描述你「實際爬到」的資料邊界，請以 `pc.capture_time` 的範圍補充一組區間：
  \[
  [C_{start},\; C_{end}]
  \]

### 2.3 SQL：查出 comment / capture 的起訖

（依你提供的 join 結構，以下以整體資料集為例）

```sql
-- 觀測期間（以評論時間 comment_date）
select
  min(pc.comment_date) as comment_date_start,
  max(pc.comment_date) as comment_date_end
from product_comments pc;

-- 爬取期間（以 capture_time）
select
  min(pc.capture_time) as capture_time_start,
  max(pc.capture_time) as capture_time_end
from product_comments pc;
```

如需依 keyword / 商品檢查：

```sql
select
  p.keyword,
  min(pc.comment_date) as comment_date_start,
  max(pc.comment_date) as comment_date_end,
  min(pc.capture_time) as capture_time_start,
  max(pc.capture_time) as capture_time_end,
  count(*) as comment_rows
from product_comments pc
left join products p on pc.product_id = p.id
group by p.keyword
order by p.keyword;
```

---

## 3️⃣ 標籤切分日（Label Split Date / Cutoff）

### 3.1 定義

- **標籤切分日（或特徵截點日）**：\(T\)  
  - 在 \(T\) 當下建立特徵（feature），並以 \(T\) 之後的資訊建立標籤（label）或目標變數。
  - 你若已在其他文件定義過（例如 `論文研究說明文件.md` 的 Time Definition：`T = 2025-06-25`），本文件沿用該 \(T\)。

> 註：若你的實驗設計不是單一 \(T\)，而是多個 rolling cutoffs（多個 \(T_1, T_2, ...\)），請在本節補上 cutoffs 產生規則（例如每 7 天取一次）。

### 3.2 SQL：快速檢查 \(T\) 前後資料量

```sql
-- 請把 :T 替換為你的 cutoff（例如 '2025-06-25'）
select
  count(*) filter (where pc.comment_date <= :T) as n_comment_le_T,
  count(*) filter (where pc.comment_date >  :T) as n_comment_gt_T
from product_comments pc;
```

---

## 4️⃣ 預測資訊只用到哪一天（Information Availability / Anti-Leakage）

本研究若以「在時間點 \(T\) 做預測」為前提，則所有可用於產生特徵的資訊必須滿足：

- **事件發生不晚於 \(T\)**：`pc.comment_date <= T`
- **資料在 \(T\) 前已被爬到/入庫**：`pc.capture_time <= T`

### 4.1 as-of \(T\) 的評論資料集（建議）

```sql
-- as-of T 的可用評論（避免使用 T 之後才爬到的資料）
select p.keyword, pc.*
from product_comments pc
left join products p on pc.product_id = p.id
where pc.comment_date <= :T
  and pc.capture_time <= :T
order by p.keyword, pc.comment_date;
```

### 4.2 常見情境說明

- **情境 A：只看事件時間（較寬鬆）**  
  - 僅限制 `comment_date <= T`。  
  - 風險：若某些評論雖然發生在 \(T\) 前，但其實是在 \(T\) 之後才被爬到（`capture_time > T`），那在「\(T\) 當下」其實不可得，會造成資訊穿越。

- **情境 B：as-of 可得性（較嚴謹，建議用於論文敘述）**  
  - 同時限制 `comment_date <= T` 與 `capture_time <= T`。  
  - 好處：可明確宣稱「模型在 \(T\) 當下能看到的資料」。

---

## 5️⃣ 需要你填入/固定的三個日期（最終寫法）

把本節當成論文可直接引用的三行定義，將日期補齊即可：

- **觀測期間（以 `pc.comment_date`）**：\(D_{start}=\) `____-__-__`，\(D_{end}=\) `____-__-__`
- **標籤切分日（cutoff）**：\(T=\) `____-__-__`
- **預測資訊截止**：僅使用滿足 `comment_date <= T` 且 `capture_time <= T` 的資料

## 🟧 Category Fit Score（1 個特徵，+Physical 輔助特徵）

> `category_fit_score` 是 +Physical 階段計算完速度特徵後、進入 +Psych 融合前的**關鍵橋接特徵**。它被 `momentum_tfidf`、`momentum_emb`、`quality_driven_momentum` 三個融合特徵引用。

| #   | 特徵名稱             | 精確說明                                                                                                                                                                                              | 完整計算步驟                                                                                                                                                                                                                                                                                                                                                                                          |
| --- | -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `category_fit_score` | **類別契合度**：衡量一個商品的評論文字與同類別（同 keyword）所有商品評論的「向心程度」（Prototypicality）。高分代表該商品的討論風格與類別主流一致（典型爆品），低分代表該商品是討論風格特立獨行的異類 | ① 按 `keyword` 將所有商品分組 ② 對每個 keyword 群組，將各商品截止日前所有評論文字合併後做 **TF-IDF 向量化**（`max_features=2000`，英文停用詞）③ 計算群組的**類別中心向量**（所有商品 TF-IDF 向量的算術平均值）④ 計算每個商品向量與類別中心的 **Cosine Distance** ⑤ `category_fit_score = 1 - Cosine Distance`（值域 [0, 1]，越高越接近類別中心）；若 keyword 群組內商品數 < 2，或全部評論為空，則填 0 |

| 值         | 意義                                                                                                      |
| ---------- | --------------------------------------------------------------------------------------------------------- |
| **接近 1** | 評論用詞與類別主流高度相似 → 「典型商品」，表達標準化體驗（例如：同品類的暢銷品都提「好用、方便、快速」） |
| **接近 0** | 評論用詞與類別主流大相逕庭 → 「異類商品」，可能是全新品類入侵者或刷評格格不入者                           |

## 🟨 +Semantic 新增（5 個特徵）

使用 BERT Zero-Shot Classification 對每則評論計算 5 個語意維度的機率值，再取近 90 天的商品平均

項目	內容
模型	MoritzLaurer/mDeBERTa-v3-base-mnli-xnli（多語言 NLI 模型，支援中文）

## 🟥 +Psych 新增（9 個特徵）

> 所有「近 90 天」均指 **2025-03-27 ~ 2025-06-25**（T-90天 至 T）

### 語意熵（Semantic Entropy）

**計算對象**：同一個商品在 2025-03-27 ~ 2025-06-25 之間，按 `comment_date DESC` 排序取最多 **100 則** 評論文字

| #   | 特徵名稱             | 精確說明                                                                                                                                 | 完整計算步驟                                                                                                                                                                                                        |
| --- | -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | `feat_entropy_tfidf` | 使用 **TF-IDF** 向量化後做 K-Means 分群，計算群組分布的 Shannon Entropy。衡量評論主題的多樣程度                                          | ① 取 2025-03-27~2025-06-25 最多 100 則評論 ② TF-IDF 向量化（`max_features=100`，英文停用詞）③ KMeans 分群（`n_clusters = min(評論數, 5)`，`random_state=42`）④ 計算各群樣本比例 ⑤ `Shannon Entropy = -Σ(p × log₂p)` |
| 2   | `feat_entropy_emb`   | 使用 **SBERT 語意嵌入**（`all-MiniLM-L6-v2`）後做 K-Means 分群，再計算 Shannon Entropy。與上相比，SBERT 能捕捉語意相似性而非關鍵字相似性 | ① 取 2025-03-27~2025-06-25 最多 100 則評論 ② SBERT `all-MiniLM-L6-v2` 編碼為 384 維向量 ③ KMeans 分群（同上，k=最多5群）④ Shannon Entropy（同上公式）                                                               |

#### 為什麼 k 最多 5 群？
```python
n_clusters = min(len(texts), 5)  # 評論不足 5 則時，群數 = 評論數
```
若商品只有 3 則符合條件的評論，則 k=3。至少需要 2 則評論才計算，否則填 0。

| 熵值                                   | 意義                                              |
| -------------------------------------- | ------------------------------------------------- |
| **接近 log₂(5) ≈ 2.32 bits（最大值）** | 5 群評論量分布均等 → 主題高度多元，各種討論都有   |
| **接近 0**                             | 所有評論落在同一群 → 主題高度集中，可能是範本刷評 |

### 時間突發性（Temporal Burstiness）

| #   | 特徵名稱                   | 精確說明                                                                                                                                 | 完整計算步驟                                                                                                                                                                                                    |
| --- | -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 3   | `feat_temporal_burstiness` | 衡量 2025-03-27~2025-06-25 期間，評論發佈時間間隔（Inter-Arrival Time, IAT）的不規律程度。範圍 [-1, 1]，需至少 3 則評論才計算，否則填 -1 | ① 取 2025-03-27~2025-06-25 期間的評論，按發佈時間排序 ② 計算相鄰評論的時間差（秒），得到 IAT 序列 ③ 僅保留 IAT > 0 的值（過濾同一秒發佈的情形） ④ `r = std(IAT) / mean(IAT)` ⑤ `Burstiness = (r - 1) / (r + 1)` |

| 值          | 意義                                                            |
| ----------- | --------------------------------------------------------------- |
| **接近 +1** | IAT 變異大 → 評論間歇性密集爆發，然後長時間沉默（典型爆品模式） |
| **接近 0**  | IAT 變異小 → 評論均勻慢速出現（穩定老品）                       |
| **接近 -1** | IAT 極度規律 → 評論以固定間隔出現（可疑機器人刷評）             |

### 詞彙多樣性（Lexical Diversity）

| #   | 特徵名稱                 | 精確說明                                                                                                                           | 完整計算步驟                                                                                                                                                                                 |
| --- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 4   | `feat_lexical_diversity` | 使用 **Guiraud's R 指標**，量化 2025-03-27~2025-06-25 期間所有評論用詞的豐富程度。高值=用詞多元（真實討論），低值=用詞重複（刷評） | ① 合併所有評論文字，以空格切詞（使用已斷詞的 tokenized 文字）② `N` = 總詞次數 ③ `V` = 不重複詞彙數 ④ `V1` = 只出現過 1 次的詞數 ⑤ `R = (100 × ln(N)) / (1 - V1/V)`；分母為 0 時替換成 0.0001 |

### 壓縮理論（Compression & Information Theory）

**計算對象**：同一商品**截止日 T 前所有評論**（非 90 天限制）的文字合併成一段字串

| #   | 特徵名稱                 | 精確說明                                                                                                                                                                     | 完整計算步驟                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| --- | ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 5   | `feat_compression_ratio` | 使用 `zlib` 壓縮演算法（LZ77），衡量合併評論的資訊密度。**值越高代表重複性越低**（真實評論難壓縮）；**值越低代表重複性越高**（刷評易壓縮）。最少需 10 字元才計算，否則填 1.0 | ① 合併商品截止日前所有評論文字 ② `original = text.encode('utf-8')` ③ `compressed = zlib.compress(original)` ④ `ratio = len(original) / len(compressed)`                                                                                                                                                                                                                                                                                                   |
| 6   | `feat_ncd_spam`          | **標準化壓縮距離（NCD）**：衡量合併評論文字與「9 個已知刷評範本字串」的相似程度。接近 0 = 極似刷評；接近 1 = 完全不像（高度個性化）。值域 [0, 1]                             | ① `x` = 商品合併評論文字 ② `y` = 9 個刷評範本（預先計算壓縮長度） ③ [C(x)](file:///c:/YvesProject/%E4%B8%AD%E5%A4%AE/%E7%B7%9A%E4%B8%8A%E8%A9%95%E8%AB%96/momo_crawler-main/seg.py#52-62) = len(zlib.compress(x)) ④ [C(x+y)](file:///c:/YvesProject/%E4%B8%AD%E5%A4%AE/%E7%B7%9A%E4%B8%8A%E8%A9%95%E8%AB%96/momo_crawler-main/seg.py#52-62) = len(zlib.compress(x + " " + y)) ⑤ `NCD = (C(x+y) - min(C(x), C(y))) / max(C(x), C(y))`，結果 clip 至 [0, 1] |

### 融合動量特徵（Fusion Features）

| --- | ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| 特徵               | 精確定義                                                                                          |
| ------------------ | ------------------------------------------------------------------------------------------------- |
| category_fit_score | 按 keyword 分組，TF-IDF(max_features=2000) → 類別中心向量 → 每商品 1 - Cosine Distance，值域[0,1] |

### +Psych（10 個）
| 特徵                     | 精確定義                                                                                         |
| ------------------------ | ------------------------------------------------------------------------------------------------ |
| feat_entropy_tfidf       | [T-90天, T] 最多100則評論 → TF-IDF(max_features=100) → KMeans(k=min(n,5)) → Shannon Entropy      |

| quality_driven_momentum  | kin_acc_abs × category_fit_score                                                                 |

## 🖤 Surrogate Structure Features（代理結構特徵，10 個）

> 這些特徵源自對 `v2_error_prod` 的 **Surrogate Rule Distillation (代理規則萃取)** 分析。
> 分析發現原先模型會誤判的商品，主要具備「高訊號但高異質性（例如：高聲量但主題發散、或正負情緒夾雜）」的特質。
> 以下特徵將這些結構特質轉為連續或二元變數，以幫助模型在不依賴硬性過濾的情況下，學習識別這類衝突樣本。
>
> P80 門檻皆以當次載入的全體商品中「該欄位非 Null」的樣本為母體動態計算。

### A. 二元互動旗標（Binary Interaction Flags）

| # | 特徵名稱 | 精確說明 | 計算條件 |
|---|---|---|---|
| 1 | `is_high_arousal_high_volume` | **高驚豔 + 高討論量**：捕捉被大量討論且具備高驚豔感的爆發性樣本。這類樣本雖然訊號極強，但容易伴隨語意發散。 | `clean_arousal_score ≥ P80`<br>AND `comment_count_90d ≥ P80` |
| 2 | `is_high_arousal_high_negative` | **高驚豔 + 高負面情緒**：捕捉存在情緒矛盾的商品（例如某些評價極高，但同時有一群人強烈反推）。 | `clean_arousal_score ≥ P80`<br>AND `bert_negative_mean ≥ P80` |
| 3 | `is_high_ncd_high_fit` | **高 NCD + 高類別契合度**：捕捉評論極度個性化、無法被壓縮，但整體用詞又非常符合該品類主流趨勢的商品。 | `feat_ncd_spam ≥ P80`<br>AND `category_fit_score ≥ P80` |

### B. 連續互動分數（Continuous Interaction Scores）

保留兩個維度乘積的強度，而非僅切斷為 0/1。

| # | 特徵名稱 | 精確說明 | 計算公式 |
|---|---|---|---|
| 4 | `interaction_arousal_volume` | **驚豔與聲量連續強度**：衡量驚豔感與聲量的複合能量，保留長尾資訊。 | `clean_arousal_score × log1p(comment_count_90d)` |
| 5 | `interaction_arousal_negative` | **情緒衝突連續強度**：量化正負情緒「同時存在」的嚴重程度，代表意見的不一致性。 | `clean_arousal_score × bert_negative_mean` |
| 6 | `interaction_ncd_fit` | **NCD與契合度連續強度**：量化高訊息量與高合群度的綜合影響。 | `feat_ncd_spam × category_fit_score` |

### C. 綜合衝突與結構特徵（Conflict & Cluster Derived）

| # | 特徵名稱 | 精確說明 | 計算公式 / 邏輯 |
|---|---|---|---|
| 7 | `conflict_signal_score` | **綜合衝突分數**：基於 SHAP Interaction 權重設計的加權指標，衡量商品在四大核心維度上的綜合「高訊號但異質」程度。 | `0.35×norm(arousal) + 0.25×norm(log1p(volume)) + 0.20×norm(neg) + 0.20×norm(entropy)` |
| 8 | `v2_surrogate_cluster_id` | **代理結構分群碼**：對全體商品的 9 個結構特徵執行 StandardScaler + KMeans (k=4) 所得的分群標籤（0~3）。 | KMeans 分群 |
| 9 | `is_cluster_like_high_complexity` | **高複雜度分群旗標**：近似代理分析中 Cluster 2 的特質。高聲量且品質驅動強，但因為高熵與高 NCD 而使模型難以對焦。 | `feat_entropy_emb ≥ P80`<br>AND `feat_ncd_spam ≥ P80`<br>AND `comment_count_90d ≥ P80`<br>AND `quality_driven_momentum ≥ P80` |
| 10 | `is_cluster_like_emotion_ad_mix` | **情緒業配混合分群旗標**：近似代理分析中 Cluster 0 的特質。驚豔感高，但同時摻雜大量的業配詞彙與負面反推。 | `bert_advertisement_mean ≥ P80`<br>AND `bert_negative_mean ≥ P80`<br>AND `clean_arousal_score ≥ P80` |

### 爬蟲設計細節
- 每次爬蟲以 `資料擷取時間 (capture_time)` 為標記，形成時間序列快照
- 支援指定截止時間（`--designate_capture_time`），只抓指定時間點之前的評論
- 評論去重機制：以 `留言ID (commentId)` 為主鍵避免重複爬取
- 防反爬：隨機暫停 0.5~1.2 秒，simulate 真實使用者行為

### Cutoff Time
- **訓練截止日**（Date Cutoff）: `2025-06-25`
- 截止日之前的評論作為特徵輸入，截止日之後的銷售變化作為標籤

### Label 定義（二元分類）

#### 標籤模式（Label Strategy）
程式支援 `absolute`（預設）與 `hybrid` 兩種：

| 策略 | 定義 | SQL 邏輯 |
|------|------|----------|
| **absolute** | 截止日後，下一批快照銷售量 Δ ≥ [delta_threshold](file:///c:/YvesProject/%E4%B8%AD%E5%A4%AE/%E7%B7%9A%E4%B8%8A%E8%A9%95%E8%AB%96/momo_crawler-main/Model/data_loader.py#74-103)（預設 10） | [(sales_count - prev_sales) >= delta_threshold](file:///c:/YvesProject/%E4%B8%AD%E5%A4%AE/%E7%B7%9A%E4%B8%8A%E8%A9%95%E8%AB%96/momo_crawler-main/build_tfidf_index.py#259-335) |
| **hybrid** | 同時需滿足絕對 Δ ≥ threshold **且** 相對成長率 ≥ `ratio_threshold`（預設 1.0 = 100%） | 同上 + [((sales_count / prev_sales) - 1) >= ratio_threshold](file:///c:/YvesProject/%E4%B8%AD%E5%A4%AE/%E7%B7%9A%E4%B8%8A%E8%A9%95%E8%AB%96/momo_crawler-main/build_tfidf_index.py#259-335) |

#### 銷售級距（Sales Buckets）
銷售量按以下離散區間分桶，label 定義基於「跨越幾個 bucket」：
```
[0, 1, 5, 10, 20, 30, 50, 100, 500, 1000, 3000, 5000, 8000, 10000, 30000, 50000, ...]
```

#### 標籤模式（Label Mode）
| 模式 | 說明 |
|------|------|
| `next_batch` | 比較截止日前後兩個最近批次的銷售量 |
| `fixed_window` | 在截止日後固定的時間窗口（`label_window_days=7`天）內，看銷售量是否達標 |

#### 正類定義（爆品 = Positive Label）
- `y = 1`：商品在截止日後的快照中銷售量顯著增加（滿足 delta + 可選 ratio 條件）
- `y = 0`：銷售量未顯著增加（非爆品）

> 最終訓練時選用 label strategy（`absolute`），以及確切的 [delta_threshold] 10.0

## 2️⃣ Preprocessing Pipeline（資料前處理流程）

### 文本處理步驟（preprocess_v2.py）

```
原始評論 CSV
  ↓ 1. 換行字元修復 (repair_broken_csv)
  ↓ 2. Unicode 正規化 (NFKC) — 全形→半形
  ↓ 3. 簡→繁轉換 (OpenCC: s2tw)
  ↓ 4. 移除 URL、控制字元、規整空白
  ↓ 5. 保留漢字，非中文替換為分隔符 ';' (sanitize_chinese)
  ↓ 6. CKIP BERT 斷詞 + POS 詞性標注 (CkipWordSegmenter, bert-base, GPU)
  ↓ 7. 長詞後向最大匹配切分 (RMM, 3字→2字→單字)
  ↓ 輸出: norm_text (CSV) + tokens/POS (JSONL)
```

### 斷詞過濾策略（seg.py + preprocess_v2.py）
- **保留詞性**：名詞 (`N*`) + 動詞 (`V*`)（CKIP POS tag）
- **去除單字詞**：`len(token) > 1` 才保留
- **不使用傳統停用詞表**：改以詞性標注自動過濾助詞、語氣詞等

### 文本特徵方法

| 方法 | 實作 | 用途 |
|------|------|------|
| **TF-IDF** | sklearn `TfidfVectorizer` (top 200 詞, max_features) | 主文本特徵（K-Fold 內 pre-fit on train_pool） |
| **SBERT Sentence Embedding** | `all-MiniLM-L6-v2` | 語意熵 (feat_entropy_emb) 計算 |
| **BERT Zero-Shot Classification** | `comment_semantic_scores` 表 | Arousal / Novelty / Repurchase / Negative / Advertisement |
| **Category TF-IDF** | 2000 維，計算品類中心點餘弦相似度 | category_fit_score |

| `is_mature_product` | 是否為成熟商品（二元旗標） | [(comment_count_pre > 50) OR (repurchase_ratio > 0.2)](file:///c:/YvesProject/%E4%B8%AD%E5%A4%AE/%E7%B7%9A%E4%B8%8A%E8%A9%95%E8%AB%96/momo_crawler-main/build_tfidf_index.py#259-335) |

## 6️⃣ Experiment Pipeline（實驗流程）

### Pipeline 設計（train_v2.py 7-Phase ML Pipeline）

```
Data (PostgreSQL DB)
│
├─ load_product_level_training_set() [data_loader.py]
│   ├─ SQL: 計算所有 Dense 特徵（SQL aggregation）
│   ├─ SQL: 計算 Label y（next_batch / fixed_window）
│   └─ Python: SBERT/TF-IDF/Compression 特徵計算
│
├─ Phase 1: 初始化 Run（run_id, output dir, Git info）
├─ Phase 2: 資料切分
│   ├─ Stratified 8:2 Holdout Split（固定 random_seed=42）
│   └─ Stratified K-Fold CV on train_pool（預設 10 folds）
├─ Phase 3: TF-IDF Prefit（僅在 train_pool 上 fit，test 只 transform）
├─ Phase 4: K-Fold 訓練迴圈
│   ├─ Dense features → FeatureTransformer（fit only on train_fold）
│   ├─ TF-IDF → slice from prefit matrix（無洩漏）
│   ├─ Merge: hstack([dense_transformed, tfidf_sliced])
│   ├─ Data Leakage Check（5項自動化洩漏檢查）
│   └─ 訓練 → 預測 OOF → 計算 AUC, F1, Precision, Recall
├─ Phase 5: 最終模型訓練（用完整 train_pool，同 prefit TF-IDF）
├─ Phase 6: Threshold 調整（fixed=0.5 / tuned=OOF F1 / locked）
└─ Phase 7: 儲存 Artifacts + 資料庫記錄
```

### 消融研究（Ablation Study）支援
- 使用 `--force-use-splits` 強制使用相同切分（保證對照實驗公平性）
- 使用 `--hyperparameter-mode locked` 鎖定超參數（消除超參誤差）
- 使用 `--threshold-mode locked` 鎖定閾值
- `split_hash / dataset_hash / feature_hash` 紀錄可復現性

## 7️⃣ Classification Model（分類模型）

### 支援的模型

| 模型 | 實作 | 超參數（預設） |
|------|------|---------------|
| **XGBoost**（主要） | `xgb.XGBClassifier` | `max_depth=6, learning_rate=0.1, n_estimators=100, tree_method=gpu_hist` |

### 類別不平衡處理
- **方法**：`scale_pos_weight`（自動計算 neg/pos 比例）
- **計算範圍**：`fold_train`（每個 fold 的訓練集各自計算），可選 `train_pool`

- LR/SVM 使用 `class_weight={0: 1.0, 1: spw}` 等效實作

### 硬體加速
- GPU 加速（`tree_method=gpu_hist`）
- 32 CPU 核心並行（`n_jobs=32`）

### 訓練策略
- **先做 K-Fold CV**（得 OOF 預測），再對完整 train_pool 訓練最終模型
- 對 test set 的最終評估完全基於最終模型預測
- 隨機種子固定（`random_seed=42`）保證可復現性

## 8️⃣ Evaluation Metrics（評估指標）

### 分類任務類型
- **二元分類（Binary Classification）**：爆品（1）vs 非爆品（0）

### 評估指標

| 指標 | 說明 | 程式實作 |
|------|------|---------|
| **ROC-AUC** | 主要比較指標；不受閾值影響 | `sklearn.metrics.roc_auc_score` |
| **F1-Score** | 精確率與召回率的調和均值（應對不平衡） | `sklearn.metrics.f1_score` |
| **Precision** | 精確率 | `sklearn.metrics.precision_score` |
| **Recall** | 召回率 | `sklearn.metrics.recall_score` |

### 評估策略

| 評估集 | 說明 | 輸出 |
|--------|------|------|
| **OOF（Out-of-Fold）Aggregate** | 每個 fold 的均值 ± 標準差 | `AUC_mean ± AUC_std, F1_mean ± F1_std` |
| **OOF Global** | 拼接所有 fold 的 OOF 預測計算 | 單一 AUC, F1, Precision, Recall |
| **Test Set** | 最終模型對 holdout 20% 的預測 | AUC, F1, Precision, Recall |

### 分類閾值（Decision Threshold）
| 模式 | 說明 |
|------|------|
| `fixed` | 固定 0.5 |
| `tuned` | 在 OOF 預測上搜尋最佳 F1（步長 0.01） |
| `locked` | 使用 baseline 實驗的最佳閾值（消融研究用） |

## 9️⃣ Data Split（資料切分）

### 切分策略

```
全部資料（N 個商品）
     ↓ Stratified 8:2 Split（random_seed=42）
┌──────────────────────────────────┐
│ Train Pool (80%)                 │
│  ↓ Stratified 10-Fold CV        │
│  ┌ Fold 0: train 9/10 + val 1/10│
│  ├ Fold 1: train 9/10 + val 1/10│
│  ├ ...                           │
│  └ Fold 9: train 9/10 + val 1/10│
└──────────────────────────────────┘
┌──────────────────────────────────┐
│ Test Set (20%)                   │
│  → 僅用於最終評估，從不參與訓練  │
└──────────────────────────────────┘
```

| 參數 | 值 |
|------|---|
| **Train/Test Split** | 80% / 20% |
| **K-Fold** | Stratified K-Fold, K=10 |
| **Random Seed** | 42（固定，保證可復現） |
| **Holdout Strategy** | Stratified（保持正負類比例） |
| **分析單位** | Product Level（每筆 = 一個商品） |

### 資料洩漏防止（Data Leakage Prevention）
- TF-IDF Vectorizer 僅 fit 在 `train_pool`（80%），test set 只 transform
- Dense 特徵的 FeatureTransformer 僅 fit 在 `train_fold`（每個 fold 的訓練部份）
- 5 項自動化洩漏檢查（[leakage_prevention.py](file:///c:/YvesProject/%E4%B8%AD%E5%A4%AE/%E7%B7%9A%E4%B8%8A%E8%A9%95%E8%AB%96/momo_crawler-main/Model/leakage_prevention.py)）於每個 fold 執行
- 截止日設計保證：特徵（cutoff 前評論）與標籤（cutoff 後銷售）嚴格分離

## 二、有效樣本形成機制（論文可用說明）

### 2.1 從原始商品到有效樣本的兩階段過濾

本研究爬蟲共取得 **7,197 件**商品基本資料，但並非所有商品均能進行分類標記。有效樣本須通過以下兩個篩選條件：

```
7,197 件商品（products 表）
   │
   │ ① 剔除無評論商品（共 2,256 件）
   │   → 無法建立評論特徵，不納入研究
   ↓
4,941 件有評論商品
   │
   │ ② 剔除評論批次無法對應銷售快照商品（共 2 件）
   │   → 無法計算銷售標籤，不納入研究
   ↓
4,939 件有效樣本（版本 A）
   │
   │ ③ 套用 v2_error_prod 品質過濾（共排除 1,210 件）
   ↓
3,729 件有效樣本（版本 B，論文正文使用）
```

### 2.2 條件一：商品必須具有評論資料

**剔除數量：2,256 件（佔 7,197 的 31.3%）**

評論資料是本研究特徵工程的核心來源（評論動能、語意分數、TF-IDF 等）。無任何評論的商品無法建立任何輸入特徵，予以排除。

### 2.3 條件二：銷售快照須能與評論批次對齊

**剔除數量：2 件**

本研究的標籤計算邏輯需要將「銷售快照」與「評論爬取批次」進行時間對齊（Temporal Alignment）。具體而言，每次爬蟲抓取評論時記錄一個批次時間（`capture_time`），對應的銷售快照須在該批次時間**之前或同時**存在，才能取得「當時的銷售量」。無法進行此對齊的商品（如：已下架、未具銷售快照）予以排除。

### 2.4 爆品標籤計算邏輯（next_batch 模式）

進入有效樣本集後，每件商品依下列流程計算二元標籤 y：

**Step 1**：依商品彙整各爬蟲批次（`capture_time`）的最新銷售量 → 形成時間序列

**Step 2**：以 `LAG()` 函數計算相鄰批次的前期銷售量（`prev_sales`）

**Step 3**：對截止日 T 後的每個批次，判斷是否滿足：

```
batch_time > T = 2025-06-25
AND prev_sales IS NOT NULL        ← 存在前一期可比較
AND (sales_count − prev_sales) ≥ 10   ← absolute 策略，Δ ≥ 10
```

**Step 4**：若**任一**批次滿足上述條件 → 標記為爆品（y = 1），否則為非爆品（y = 0）

### 2.5 各批次數分佈

爬蟲共進行 **2～9 次**不同時間點的捕獲（部分商品只被爬取一次）：

| 批次數 | 商品數 |
|:---:|:---:|
| 1 | 1,929 |
| 2 | 1,055 |
| 3 |   749 |
| 4 |   704 |
| 5 |   357 |
| 6～9 |   145 |
| **合計** | **4,939** |

> [!NOTE]
> 僅有 1 個批次的商品（1,929 件）無法計算前後期銷售差 Δ（因 `prev_sales = NULL`）；此類商品一律標記為 y = 0（非爆品），仍納入訓練集以保留資料規模。
>
> 在 4,939 件有效樣本中，真正具有「截止日後 AND 有前期對比」能力的商品共 **2,899 件**；其餘 2,040 件因僅有截止前資料或只有單一批次，標籤 y = 0 是基於「未觀察到爆品行為」的保守假設。

### 2.6 v2_error_prod 品質過濾（版本 B）

**v2_error_prod** 是一套以模型集成誤差（Ensemble Error）為依據的商品品質過濾機制，旨在移除高雜訊或高異質性樣本，使訓練集更具一致性：

- 以 4 種特徵組合（Base / Price / Kin / Nov）分別訓練 XGBoost（10-Fold Cross-Validation）
- 凡在 **≥ 3/4 個模型中均預測錯誤**的商品，視為標籤行為難以學習的異常樣本
- 共排除 **1,210 件**（佔版本 A 有效樣本 4,939 的 24.5%）

此過濾的目的是提升模型訓練訊號的品質，非作為資料集代表性的篩選依據：
- 由於排除了 1,210 件商品，專屬於這些商品的評論也連帶不進入模型訓練，因此總訓練評論數由 132,640 筆降至 87,849 筆（減少約 33.8%）。
- 爆品正類比例從 9.4%（版本 A）輕微降至 9.1%（版本 B）。

# 研究說明文件（Research Brief）

## 使用線上評論訊號預測商品熱門度

### 一、研究概述（Research Overview）

本研究旨在探討**線上商品評論所包含的訊號，是否能夠有效預測商品的熱門程度（product popularity）**。隨著電子商務平台的快速發展，消費者在購買商品前，往往會參考其他使用者所留下的評論內容，因此評論資料不僅能反映消費者滿意度，也可能隱含商品傳播與市場關注度的重要訊號。

本研究的主要目標，是透過建立多種類型的評論衍生特徵（review-derived features），並結合機器學習模型，評估不同特徵類型對於商品熱門度預測的影響。

本研究將嘗試回答以下研究問題：

**RQ1：** 評論數量的時間動態變化，是否有助於預測商品熱門度？
**RQ2：** 從評論文本中擷取的語意訊號，是否能提升預測模型的效果？
**RQ3：** 評論行為與資訊結構特徵，是否能提供額外的預測能力？

為回答上述問題，本研究將建立多種評論特徵群組，並透過機器學習模型進行比較分析。

---

### 二、資料集說明（Dataset Description）

本研究使用的資料來自台灣電子商務平台 **Momo購物網**。研究中透過 Python 爬蟲程式收集商品資訊、商品評論，以及不同時間點的銷售數量資料。

資料集包含以下主要資訊：

* 商品 ID（product_id）
* 商品價格（price）
* 評論文字內容（review text）
* 評論評分（1–5 星）
* 評論時間（timestamp）
* 評論按讚數（like_count）
* 不同時間點的商品銷售數量

為確保研究資料的一致性，本研究首先透過關鍵字搜尋建立**初始商品集合（initial product set）**。在此之後，商品清單將保持固定，後續資料收集僅更新既有商品的評論資料與銷售資料，而不再新增新的商品。

這樣的設計可以追蹤**商品評論活動與商品熱門度的時間變化**，並避免因新商品加入所造成的資料波動。

---

### 三、時間定義（Time Definition）

本研究所有時間相關特徵皆以一個固定的 **特徵截點日期（feature cutoff date）** 為基準：

**T = 2025-06-25**

研究中定義以下時間區間：

| 時間區間    | 定義           |
| ------- | ------------ |
| 過去 7 天  | T − 7 天 至 T  |
| 過去 30 天 | T − 30 天 至 T |
| 過去 90 天 | T − 90 天 至 T |

這些時間區間將用於計算評論動態相關特徵，例如評論成長速度與評論活動比例。

---

### 四、特徵類型（Feature Categories）

本研究從商品評論資料中建立四種類型的特徵：

* Baseline features（基礎特徵）
* Physical features（評論動態特徵）
* Semantic features（語意特徵）
* Psych features（評論行為特徵）

其中 Baseline features 作為基本統計特徵，其餘三類則代表不同的分析視角。

---

### 4.1 Baseline Features（基礎特徵）

Baseline features 描述商品評論的基本統計特性與商品基本屬性。

主要包含：

* 商品價格
* 評論總數
* 平均評分
* 評分變異數
* 評論按讚數
* 評論近期比例
* 不同時間區間內的評論數量

這些特徵提供商品評論活動的基本描述。

---

### 4.2 Physical Features（評論動態特徵）

Physical features 用來描述**評論數量隨時間變化的動態行為**。此類特徵的設計概念來自於運動學（kinematics），將評論成長視為一種動態過程。

主要指標包括：

* 評論速度（review velocity）：每週新增評論數
* 評論加速度（review acceleration）：評論成長速度的變化
* 評論 jerk（加速度變化率）
* 商品初期評論成長動能

這些特徵的目的，是偵測商品評論是否出現快速成長的現象，進而反映商品可能正在受到市場關注。

---

### 4.3 Semantic Features（語意特徵）

Semantic features 用來捕捉**評論文字中的情緒與消費者意圖訊號**。

本研究使用多語言自然語言推論模型（multilingual Natural Language Inference, NLI），以 **zero-shot classification** 的方式對評論文本進行語意分析。

每則評論將與多個語意假設進行比對，並產生不同語意維度的機率分數。

主要語意維度包括：

* 情緒興奮程度（arousal）
* 新奇感（novelty perception）
* 再購意圖（repurchase intention）
* 負面抱怨（complaints）
* 類廣告式評論（template-style reviews）

最後將各評論的語意分數在 90 天視窗內進行聚合，形成商品層級的語意特徵。

---

### 4.4 Psych Features（評論行為特徵）

Psych features 用來描述**評論整體資訊結構與群體行為模式**。

此類特徵試圖捕捉評論在資訊多樣性、時間分布與潛在操控行為上的特性。

主要指標包括：

* 評論主題語意熵（semantic entropy）
* 評論時間突發性（temporal burstiness）
* 詞彙多樣性（lexical diversity）
* 壓縮資訊密度（compression-based information density）
* 與垃圾評論模板的相似度

這些特徵可用來觀察商品評論是否呈現出高度集中或異常的評論模式。

---

### 五、實驗特徵組合（Experimental Feature Sets）

為了評估不同特徵類型的影響，本研究建立以下四組特徵組合：

1. Baseline
2. Baseline + Physical
3. Baseline + Semantic
4. Baseline + Psych

每一組特徵將分別用於訓練預測模型，以比較不同特徵類型對預測效果的影響。

---

### 六、預測模型（Prediction Model）

本研究使用 **XGBoost** 作為主要分類模型。

XGBoost 是一種基於梯度提升（Gradient Boosting）的機器學習方法，具有以下優點：

* 能處理非線性關係
* 能有效建模特徵交互作用
* 在結構化資料上具有良好預測效果

模型將利用不同特徵組合來預測商品熱門度。

---

### 七、評估指標（Evaluation Metrics）

模型預測效果將使用以下指標進行評估：

* Precision（精確率）
* Recall（召回率）
* F1 Score
* ROC-AUC

這些指標可同時衡量模型的預測準確度與分類平衡能力。

---

本研究說明文件主要用於輔助：

1. 文獻回顧與相關研究整理
2. 研究方法設計說明
3. 論文方法章節撰寫
4. 建立研究架構與實驗設計的理論依據

透過結合相關學術文獻，本研究將進一步確認不同評論特徵類型的理論基礎，並將研究方法與既有研究成果進行連結。
