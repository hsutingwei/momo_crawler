# 文本前處理與斷詞工程分析

本文檔根據 `preprocess_v2.py` 之原始碼，梳理實際的文本前處理與斷詞執行流程。以作為後續特徵工程與模型建構的基礎。

## 一、高階流程圖節點列表 (論文架構用)

此層級可作為論文 3.3.3 節的流程圖文字說明：

1. **資料讀取與格式修復**：讀取原始 CSV，並修復因斷行產生的格式錯誤。
2. **無效與重複資料排除**：驗證欄位完整性，並透過評論 ID 排除重複抓取的資料。
3. **基礎文字正規化**：將商品名稱與評論文本進行 Unicode 統一化、繁簡轉換、並清除網址與控制字元。
4. **字元過濾與替換**：過濾非中文字符與特殊標點，並將其替換為特定分隔符號 (`;`) 以保留斷句結構。
5. **空文本檢驗**：若清理後文本為空，則判定無實質語意並跳過後續詞彙處理。
6. **CKIP 斷詞與詞性標記**：將通過保留的中文句子交由預訓練之 CKIP Transformer 模型進行分詞與詞性標記。
7. **長詞彙拆分優化**：針對分詞過長之字詞 (>4字)，透過資料庫中的輔助子詞字典進行「右向左最大匹配」拆分。
8. **結果聚合與輸出**：將正規化後的文本與對應的標記結果儲存為 CSV 與 JSONL 格式供後續使用。

## 二、詳細流程圖節點列表 (反映程式邏輯)

本列表精確反映程式碼中的先後執行邏輯、輸入輸出關係與條件分支。

### 步驟 1：修復斷行與讀取 (repair_broken_csv)
*   **輸入**：原始爬蟲 CSV（例如 `<keyword>_商品留言資料_<ts>.csv`）
*   **處理動作**：使用正規表示式逐行檢查是否以 `流水號,` 開頭；若否，則合併至上一行。
*   **輸出**：修復後的暫存 CSV 檔案 `_tmp_...csv`。

### 步驟 2：欄位與重複驗證 (process_file - Iterate CSV)
*   **輸入**：逐筆讀出 `_tmp_...csv` 之中每一列 (row)
*   **處理動作 & 條件判斷**：
    *   **條件 A**：欄位長度是否 `< 7`？
        *   *[分支：是]* → 視為無效行，並 **排除該筆評論**。
        *   *[分支：否]* → 繼續。
    *   **條件 B**：提取 `msg_id` (`row[6]`) 是否已存在於 `seen_ids` 集合？
        *   *[分支：是]* → 視為重複，並 **排除該筆評論**。
        *   *[分支：否]* → 繼續，並登記至集合中。
*   **輸出**：有效的原始商品名稱與留言字串。

### 步驟 3：基礎文字正規化 (normalize_text)
*   **輸入**：原始商品名稱 `row[1]` 與原始留言 `row[5]`
*   **處理動作**：
    1.  **Unicode 正規化**：執行 `unicodedata.normalize('NFKC', s)` 處理半形與全形等相異編碼。
    2.  **繁簡轉換**：執行 OpenCC (`s2tw`) 將簡體中文轉為台灣繁體。
    3.  **特殊符號清理(URL)**：使用正規表示式移除網址 (http/www) 並以空白替換。
    4.  **特殊符號清理(控制字元)**：移除 `\u0000-\u001F` 等十六進制控制字元並以空白替換。
    5.  移除多餘空白片段使其為單一空白。
*   **輸出**：初步清洗過之正規化字串 `norm_text`。

### 步驟 4：中文字元過濾 (sanitize_chinese)
*   **輸入**：初清洗的 `norm_text` 字串
*   **處理動作**：
    1.  **非中文字符清理**：將所有非 CJK (中日韓越漢字) 編碼範圍內的字元，強制替換成符號 `;`。這意味著**英文及數字都會被排除並被視為分隔符**。
    2.  **特殊符號替換**：明確將大部分之各類標點、注音符號等強制轉為符號 `;`。
    3.  連續之分隔符號 (`;;;`) 自動合併為單次 `;`。移除頭尾的分隔符。
*   **輸出**：僅保留各種漢字，其餘皆被分號區隔的文本段落。

### 步驟 5：斷詞判定與 CKIP 分詞 (ckip_tokenize)
*   **輸入**：經過字元過濾後的 `norm_text`
*   **處理動作 & 條件判斷**：
    *   **空字串判定**：判斷 `if not norm_text:`
        *   *[分支：是]* → 即留言只含網址、純英數等，**排除後續分析，回傳空詞彙與空詞性 `([], [])`**，進入步驟 7 輸出。
        *   *[分支：否]* → 繼續進入 CKIP 分詞引擎。
    *   分詞處理：調用 GPU 加速之 `CkipWordSegmenter` 進行文本分詞，以及 `CkipPosTagger` 進行詞性還原（POS標記）。
*   **輸出**：斷詞列表 `tokens` 與 詞性列表 `poses`。

### 步驟 6：長詞彙拆分補強 (split_long_tokens_with_pos_rmm)
*   **輸入**：斷詞與詞性陣列、長度2至3之輔助字典 `dict_set`
*   **處理動作**：
    *   若單一 token 長度大於 4 (包含 5 以上)：
        *   優先比對字典內的 3 個字子詞，若不匹配則比對 2 個字。
        *   以最大反向匹配 (由右向左切)，確保末端詞語結構；拆解後的附屬子詞繼承此 token 最原本的詞性。
*   **輸出**：最終優化與細碎化後之 `out_tokens, out_poses`。

### 步驟 7：資料輸出組合
*   **輸入**：最終的文字與陣列與 ID。
*   **處理動作**：將 `norm_text` 附加為 CSV 新欄位、並打包 JSON 格式。
*   **輸出**：產生 `pre_..._norm.csv` 與 `pre_..._tokens.jsonl`，準備進入下階段的 TF-IDF 頻次抽取。

## 三、 特殊處理邏輯清單檢驗總結

*   **☑ Unicode 正規化**：有，調用 `unicodedata.normalize('NFKC', s)`。
*   **☑ 繁簡轉換**：有，調用 `OpenCC('s2tw')`。
*   **☑ 非中文字符清理**：有，透過正則 `[^\u3400-\u9fcc..]` 匹配，將英、數等非漢字強制替換為分號。
*   **☑ 特殊符號清理**：有，結合了控制字元、網址過濾以及人工定義的數百種特殊標點，皆強制過濾為分號。
*   **☑ 空字串判定**：有，清理後若無實質語意將不傳入 CKIP 並直接回傳空陣列跳過分析。
*   **☒ 停用詞處理 (無顯式實作)**：本階段未執行將「的、了、是」等停用詞直接自 tokens 中移除的動作，斷詞結果包含所保留的所有中文字。
*   **☑ CKIP 斷詞**：有，完整導入 `ckip_transformers` 進行分詞與詞性標注。
*   **☑ 其他額外清洗邏輯**：包含 CSV 的跨行讀取修復容錯，以及自行編寫的**長詞輔助切分器 (RMM)** 邏輯。
