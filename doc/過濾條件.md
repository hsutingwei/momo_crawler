# Spam 訊號商品過濾機制 (v5)

## 概述

本過濾機制包含三個版本的過濾條件，專門用來抓出「**可能具有刷評嫌疑（不符合自然 eWOM 擴散機制）**」的異常商品。
執行生成腳本後，符合條件的商品 ID (`product_id`) 將會寫入資料庫的 `public.ml_data_filters` 資料表中，供機器學習訓練腳本 (`train_v2.py`) 透過 `--apply-filter-tag` 參數進行排除，防止這些極端異常資料干擾模型訓練。

---

## 核心異常訊號 (Features)

這三個版本皆主要基於以下三個異常訊號進行判斷：

1. **`feat_entropy_emb`（語意熵）**：
   衡量該商品底下評論的「主題多樣性」。值越低，代表評論長得越像、同質性越高（越有可能是罐頭刷評）。
2. **`feat_ncd_spam`（標準化壓縮距離）**：
   衡量該商品評論與已知「刷評範本」的相似度。值越低，代表與刷評範本越像。
3. **`kin_acc_abs`（評論聲量絕對加速度）**：
   衡量近期評論數量的爆發力。值越高，代表近期聲量異常飆升（典型刷評的特徵之一）。

---

## 空缺值 (Null) 與極端值處理規則

為了確保每一次執行產生的過濾名單都穩定且可重現，針對有缺值或異常值的商品，統一採取以下處理規則：

* **`feat_entropy_emb` 是 NULL 時**：補值為 `1.0`。視為語意多樣性正常（最不可疑），不會因為缺漏值就將其當作 spam。
* **`feat_ncd_spam` 是 NULL 時**：補值為 `1.0`。視為與範本距離遙遠（最不可疑）。
* **`kin_acc_abs` 是 NULL 或負值時**：NULL 補值為 `0`；若為負數，一律統一裁切 (clip) 成 `0`。確保不會有負值影響後續正規化計算。
* **`normalized_kin_acc_abs` 計算**：會先找出全體的最大加速度 (`max(kin_acc_abs)`)，如果最大值也是 0，則所有商品的正規化加速度皆為 `0`。

---

## 三種過濾版本詳細定義

### 1. `v5_spam_fixed_prod` (固定閾值版)

採用**絕對且嚴格的門檻**，必須同時滿足所有極端異常條件才會被抓入黑名單。寧缺勿濫，抓出來的商品嫌疑非常高。

* **過濾條件（需同時滿足）**：
  1. `feat_entropy_emb < 0.5` （評論語意高度集中、太單一）
  2. `feat_ncd_spam < 0.4` （與已知刷評範本長得非常像）
  3. `comment_count_90d > 5` （近 90 天內至少有 5 則以上評論，避免樣本太少造成數據不穩定的誤判）
* **資料庫紀錄欄位**：
  * `reason`: `spam_fixed_threshold`
  * `score`: 該商品的 `kin_acc_abs` (補 0 後的值)

### 2. `v5_spam_quantile_prod` (分位數/大盤相對版)

根據「**當下資料庫中的全體商品分布**」動態決定門檻。尋找在各項異常訊號上「最極端」的群體。

* **分位數計算母體 (Population)**：
  > 僅在上述三個關鍵欄位均非 NULL，**且**近 90 天評論數 > 5 筆的所有商品中計算分位數。
* **過濾條件（需同時滿足）**：
  1. `feat_entropy_emb` ≤ 母體的 **10% 分位數 (P10)**
  2. `feat_ncd_spam` ≤ 母體的 **10% 分位數 (P10)**
  3. `kin_acc_abs` ≥ 母體的 **80% 分位數 (P80)**
  4. `comment_count_90d > 5` （防護機制）
* **資料庫紀錄欄位**：
  * `reason`: `spam_quantile_threshold`
  * `score`: 該商品的 `kin_acc_abs` (補 0 後的值)

### 3. `v5_spam_score_top5_prod` (Spam Score 綜合評分版)

不要求所有條件都極端，而是將三個異常訊號融合計算成一個「**綜合嫌疑分數 (`spam_score`)**」，抓取分數最高的前 5% 商品。可以有效抓出「偏科型」刷評（例如：聲量爆發平平，但語意完全是範本照抄的商品）。

* **分數計算公式**：
  `spam_score = (1 - feat_entropy_emb) * 0.4 + (1 - feat_ncd_spam) * 0.4 + normalized_kin_acc_abs * 0.2`
  *(分數越高，代表同質性越高、越像範本、或爆發力越強，綜合起來越可疑)*
* **過濾條件**：
  * 該商品的 `spam_score` 落在全體商品的 **Top 5%** 以上（即 ≥ P95）。
* **資料庫紀錄欄位**：
  * `reason`: `spam_score_top5`
  * `score`: 計算出的 `spam_score` 數值

## 指令參考

### 產生過濾清單寫入資料庫
由 `build_spam_filters.py` 腳本執行。每一次執行前，腳本會自動將資料庫內相同 `version_tag` 的舊資料刪除，確保每次產生的都是最新淨化的完整清單（具備冪等性）。

```bash
# 一次產生 3 個版本的過濾清單
python Model/build_spam_filters.py --date-cutoff 2025-06-25

# 查詢驗證
# psql -c "SELECT version_tag, COUNT(*) AS cnt FROM public.ml_data_filters WHERE version_tag IN ('v5_spam_fixed_prod', 'v5_spam_quantile_prod', 'v5_spam_score_top5_prod') GROUP BY version_tag;"
```

### 模型訓練套用
模型訓練會抓取資料庫當中的名單，直接在 Feature Splitting 前自動排除這些商品。

```bash
# 範例一：套用固定閾值版
python Model/train_v2.py \
    --date-cutoff 2025-06-25 \
    --feature-set baseline \
    --run-id baseline_v5_fixed \
    --group-id v5_spam_test \
    --n-folds 5 \
    --apply-filter-tag v5_spam_fixed_prod

# 範例二：套用綜合評分版
python Model/train_v2.py \
    --date-cutoff 2025-06-25 \
    --feature-set baseline \
    --run-id baseline_v5_score \
    --group-id v5_spam_test \
    --n-folds 5 \
    --apply-filter-tag v5_spam_score_top5_prod
```

# Consumer Skepticism 評價脫鉤過濾機制 (v6)

## 概述

這個過濾機制包含兩個版本的過濾條件，專門用來標記「**高業配感，但其成長可能不是由平台內評論自然驅動**」的可疑商品。
與 v5 最大的不同在於，v6 **只針對模型標記為正樣本（`y = 1`）的商品**進行過濾，藉此移除那些「評價說服力低，但後續依然爆發」的不合理正樣本。

---

## 核心異常訊號 (Features)

1. **`bert_advertisement_mean` (廣告業配平均分數)**：
   BERT 模型判定該商品近期評論屬於「廣告/業配/空泛宣傳」的機率平均值。
2. **`quality_driven_momentum` (品質驅動之聲量動量)**：
   由「聲量爆發力」乘上「與該分類屬性的契合度」所派生，代表該爆發有多少程度是由「真實討論商品品質」所支撐。
3. **`clean_arousal_score` (純淨驚豔分數)**：
   去除負面情緒、去除業配感後的純淨驚豔情緒分數。

---

## 兩種過濾版本詳細定義

### 1. `v6_ad_disconnect_prod` (基礎版：高業配感爆發樣本)

單純抓取「雖然業配感極高，但後續依然爆發」的違和正樣本。

* **分位數計算母體**：`bert_advertisement_mean` 非 null 的所有商品
* **過濾條件（需同時滿足）**：
  1. `y = 1` （該商品為爆發正樣本）
  2. `bert_advertisement_mean` ≥ 母體的 **90% 分位數 (P90)** （業配感名列前 10% 高）
* **資料庫紀錄欄位**：
  * `reason`: `high_advertisement_disconnect`
  * `score`: 該商品的 `bert_advertisement_mean`

### 2. `v6_ad_disconnect_strict_prod` (強化版：高業配感 + 低品質支撐 + 爆發)

這是一個非常嚴格的條件，尋找「高業配感 + 缺乏品質討論支撐 + 缺乏純淨驚豔情緒支撐，卻依然爆發」的三重異常商品。

* **分位數計算母體**：三欄均非 null 的所有商品
* **過濾條件（需同時滿足）**：
  1. `y = 1`
  2. `bert_advertisement_mean` ≥ 母體的 **90% 分位數 (P90)** （業配感前 10% 高）
  3. `quality_driven_momentum` ≤ 母體的 **30% 分位數 (P30)** （品質動量後 30% 低）
  4. `clean_arousal_score` ≤ 母體的 **30% 分位數 (P30)** （純淨驚豔後 30% 低）
* **資料庫紀錄欄位**：
  * `reason`: `ad_disconnect_low_quality_support`
  * `score`: 綜合分數 (`bert_advertisement_mean - quality_driven_momentum - clean_arousal_score`)

---

## 指令參考

### 產生過濾清單寫入資料庫
```bash
python Model/build_ad_disconnect_filters.py --date-cutoff 2025-06-25
```

### 模型訓練套用
```bash

    --run-id baseline_v6_ad_disconnect \
    --group-id v6_ad_test \
    --n-folds 5 \
    --apply-filter-tag v6_ad_disconnect_prod
```

# 衝突型 Proxy Filter 機制 (v8)

## 概述

本過濾機制包含三個版本，源自對 `v2_error_prod` 的 **Surrogate Rule Distillation 分析**。
分析發現 `v2_error_prod` 最常排掉的不是明顯低品質商品，而是「**高訊號但訊號方向不一致**」的樣本，也就是不同特徵指向不同結論、造成模型學習邊界不穩定的正樣本。

這三個版本均**只針對 y = 1 的正樣本**進行過濾。

---

## 核心異常訊號 (Features)

1. **`comment_count_90d`（近 90 天評論數）**：surrogate 分析中 `v2_error_prod` 最強單一區分特徵，z=1 的商品評論數顯著偏高。
2. **`feat_entropy_emb`（語意熵）**：z=1 商品的語意複雜度明顯高於 z=0，反映評論內容多元且難以被單一語意方向概括。
3. **`clean_arousal_score`（純淨驚豔分數）**：z=1 商品同時伴隨高驚豔情緒。
4. **`bert_negative_mean`（BERT 負面情緒平均）**：z=1 商品同時帶有高負面情緒，與高驚豔感並存形成衝突。

---

## 三種過濾版本詳細定義

### 1. `v8_conflict_volume_entropy_prod`（高聲量 + 高語意複雜度）

捕捉「評論量高且語意複雜度高」的爆發正樣本。這類商品訊號非常強，但因為評論多元複雜，模型難以找到一致的學習方向。

* **分位數計算母體**：`comment_count_90d` 與 `feat_entropy_emb` 均非 null 的所有商品
* **過濾條件（需同時滿足）**：
  1. `y = 1`
  2. `comment_count_90d` ≥ 母體的 **P80**
  3. `feat_entropy_emb` ≥ 母體的 **P80**
* **資料庫紀錄欄位**：
  * `reason`: `high_volume_high_entropy_conflict`
  * `score`: `comment_count_90d + feat_entropy_emb`

### 2. `v8_conflict_emotion_mix_prod`（高正向情緒 + 高負向情緒）

捕捉「評論中同時存在高驚豔感與高負面情緒」的爆發正樣本。情緒訊號相互矛盾，模型對這類樣本的判斷邊界不穩定。

* **分位數計算母體**：`clean_arousal_score` 與 `bert_negative_mean` 均非 null 的所有商品
* **過濾條件（需同時滿足）**：
  1. `y = 1`
  2. `clean_arousal_score` ≥ 母體的 **P80**
  3. `bert_negative_mean` ≥ 母體的 **P80**
* **資料庫紀錄欄位**：
  * `reason`: `high_arousal_high_negative_conflict`
  * `score`: `clean_arousal_score + bert_negative_mean`

### 3. `v8_conflict_union_prod`（Rule 1 ∪ Rule 2 聯集）

符合 Rule 1 **或** Rule 2 任一條件即納入（OR 邏輯），涵蓋更廣義的「高訊號但不一致」樣本。

* **過濾條件**：符合 `v8_conflict_volume_entropy_prod` **或** `v8_conflict_emotion_mix_prod` 任一條件
* **資料庫紀錄欄位**：
  * `reason`: `conflict_union_rule`
  * `score`:
    * 只符合 Rule 1：Rule 1 的 score
    * 只符合 Rule 2：Rule 2 的 score
    * 同時符合兩條：Rule 1 score + Rule 2 score

---

## 指令參考

### 產生過濾清單寫入資料庫
```bash
python Model/build_conflict_proxy_filters.py --date-cutoff 2025-06-25
```

### 模型訓練套用
```bash
# Rule 1: 高聲量 + 高語意複雜度版

    --date-cutoff 2025-06-25 \
    --feature-set baseline \
    --run-id baseline_v8_vol_entropy \

    --n-folds 5 \
    --tfidf-dim 0 \
    --apply-filter-tag v8_conflict_volume_entropy_prod

python Model/train_v2.py \
    --date-cutoff 2025-06-25 \
    --feature-set baseline \
    --run-id baseline_v8_union \
    --group-id v8_conflict_test \
    --n-folds 5 \
    --tfidf-dim 0 \
    --apply-filter-tag v8_conflict_union_prod
```
